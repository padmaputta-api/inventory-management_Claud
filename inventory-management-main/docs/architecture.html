Architecture Overview

Factory Inventory Management System

Full-stack web application for tracking factory inventory, orders, demand forecasts, spending, and backlog — with real-time filtering and multi-language support.

Request / Data Flow
1
Server Startup — Data Loaded into Memory
mock_data.py reads all 7 JSON files from server/data/ into module-level Python lists at import time. FastAPI and Pydantic models are registered. Uvicorn begins listening on port 8001.
2
User Loads Page — Vue Mounts
Vite serves the Vue app to the browser. main.js creates the app, registers vue-router, and mounts to #app. The router renders the matching view component for the current URL.
3
View Mounts — Initial API Call
Each view's onMounted() calls a loadData() function. This reads current filter state from the useFilters() singleton composable and invokes the relevant api.js method.
4
API Call — HTTP GET with Filter Params
Axios sends a GET request such as GET /api/orders?warehouse=Tokyo&status=Delivered&month=2025-01. Filter values of "all" are omitted from the query string.
5
Backend Filters In-Memory Data
The FastAPI route handler calls apply_filters() for warehouse / category / status (case-insensitive), then filter_by_month() which supports both direct month strings (2025-01) and quarter tokens (Q1-2025).
6
Pydantic Validates & Serializes Response
FastAPI passes the filtered Python dicts through the response_model Pydantic class. Fields are validated and the response is serialized to JSON and returned with 200 OK.
7
Vue Updates Reactive State
Axios resolves the promise. The view stores the response array in a ref(). Computed properties automatically re-derive sorted/formatted data. Vue's reactivity system patches only the changed DOM nodes.
8
Filter Change — Cycle Repeats
When a user selects a different filter value in FilterBar.vue, the shared ref in useFilters() updates. All active views have a watch() on these refs that calls loadData() again — restarting from step 4.
API Endpoints
GET/api/inventoryAll inventory items. Filters: warehouse, category
GET/api/inventory/{item_id}Single inventory item by ID
GET/api/ordersAll orders. Filters: warehouse, category, status, month (or Q1–Q4)
GET/api/orders/{order_id}Single order with line items
GET/api/demandDemand forecasts (no filters). Returns trend: increasing / stable / decreasing
GET/api/backlogBacklog items with computed has_purchase_order flag
GET/api/dashboard/summaryKPI summary — inventory value, low stock count, pending orders, backlog count

Order Status
allDeliveredShippedProcessingBackordered
Applies to: Orders, Dashboard
How it works: All four filters live as module-level ref() values inside useFilters.js — a singleton composable. FilterBar.vue binds to these refs via v-model. Every view that cares about filters calls useFilters() and sets up a watch() on the relevant refs. When a filter changes, the watch fires loadData(), which calls getCurrentFilters() to build the query params object, passes it through api.js, and re-fetches from the backend. Inventory does not support the month or status filters (no time dimension in stock data).
